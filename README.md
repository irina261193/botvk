# VK AI Sales Bot — продавец материалов

AI-бот для сообщений сообщества ВКонтакте. Бот консультирует пользователей, помогает подобрать подходящие учебные материалы и мягко подводит заинтересованного пользователя к покупке.

## 1. Цель проекта

Пользователь пишет в сообщения сообщества ВК. Бот:

1. Приветствует пользователя.
2. Понимает вопрос в свободной форме.
3. Уточняет потребность, если информации недостаточно.
4. Учитывает контекст текущего диалога.
5. Помнит до 10 последних сообщений пользователя и связанные с ними ответы бота.
6. Использует базу знаний из `knowledge.md`.
7. Подбирает только реально существующие материалы.
8. Отвечает на вопросы о материалах, составе, возрасте, уровне, теме, цене и покупке.
9. Мягко предлагает подходящий материал, когда это уместно.
10. Не выдумывает товары, цены, ссылки, скидки, условия или характеристики.
11. При необходимости предлагает обратиться к администратору.

Главная задача — не навязчивая продажа, а полезная консультация и подбор материала под конкретного ученика/преподавателя.

## 6. Основной сценарий

### Новый пользователь

При первом сообщении бот отвечает фиксированным приветствием:

> Здравствуйте! 👋 Чем я могу помочь?

Приветствие не обязательно отправлять в AI — это экономит запросы и делает поведение предсказуемым.

### Продолжение диалога

После приветствия:

1. Получить `user_id`.
2. Получить историю этого пользователя.
3. Добавить новое сообщение.
4. Оставить ограниченный контекст последних сообщений.
5. Загрузить правила из `knowledge.md`.
6. При необходимости получить подходящие товары из `products.json`.
7. Сформировать запрос к Kie.ai.
8. Получить ответ.
9. Проверить, что ответ не содержит выдуманных данных.
10. Отправить ответ в VK.
11. Сохранить ответ в SQLite.

## 7. Память

Память должна быть отдельной для каждого `VK user_id`.

Требование: учитывать до 10 последних пользовательских сообщений и соответствующий контекст ответов ассистента.

Пример:

```text
user
assistant
user
assistant
...
```

SQLite предпочтительнее хранения истории только в оперативной памяти, потому что после перезапуска BotHost данные в RAM исчезнут.

Пример таблицы:

```sql
CREATE TABLE IF NOT EXISTS messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    role TEXT NOT NULL,
    content TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

При формировании контекста выбирать только необходимую последнюю часть истории.

## 8. Каталог товаров

Каталог хранить отдельно от AI-промта в `data/products.json`.

Пример:

```json
[
  {
    "id": "weather_001",
    "title": "Weather",
    "active": true,
    "price": 350,
    "currency": "RUB",
    "type": "lesson",
    "age_min": 7,
    "age_max": 9,
    "level": ["beginner", "A1"],
    "topics": ["weather"],
    "characters": [],
    "description": "Материал для урока английского языка по теме Weather.",
    "includes": ["presentation", "tasks"],
    "buy_url": ""
  }
]
```

AI может рекомендовать только позиции с `active: true`.

Если товара в каталоге нет, бот не имеет права придумывать его.

## 9. Логика подбора

При запросе желательно определить:

- возраст ученика;
- уровень;
- тему;
- формат;
- интересы/любимых персонажей;
- конкретную проблему преподавателя.

Не нужно задавать все вопросы подряд. Уточнять только то, что действительно требуется для хорошего подбора.

Пример:

```text
Пользователь:
Нужно что-нибудь для девочки 8 лет.

Бот:
Конечно 😊 Какой у неё примерно уровень и какую тему хотите отработать?

Пользователь:
Начинающая, сейчас погода.

Бот:
[подбирает существующие товары по возрасту, уровню и теме]
```

---

## 10. Продажи без давления

Бот не должен пытаться продать материал в каждом сообщении.

Логика:

```text
HELP → DISCOVER → RECOMMEND → EXPLAIN → HANDLE OBJECTION → PURCHASE
```

Возможные состояния:

- `NEW` — начало общения;
- `QUESTION` — обычный вопрос;
- `DISCOVERY` — выяснение потребности;
- `INTEREST` — пользователь заинтересован;
- `OBJECTION` — сомнение/возражение;
- `READY_TO_BUY` — явное намерение купить;
- `HANDOFF` — требуется администратор.

Эти состояния необязательно хранить как жёсткую конечную машину состояний на первом этапе. Они описывают желаемое поведение AI.

---

## 11. Правила AI

Системный промт должен включать содержимое `knowledge.md` и строгие ограничения:

- не выдумывать товары;
- не выдумывать цены;
- не выдумывать ссылки;
- не обещать скидки без данных;
- не придумывать содержание материала;
- не утверждать наличие товара, если его нет в каталоге;
- не спорить с пользователем;
- не давить;
- не отправлять длинные рекламные полотна без необходимости;
- отвечать прежде всего на вопрос человека;
- при неизвестной информации честно сообщать, что её нужно уточнить у администратора.

---

## 12. Обработка покупки

Когда пользователь явно хочет купить материал:

1. Определить конкретный товар.
2. Повторно проверить данные товара.
3. Назвать точную цену только из каталога.
4. Отправить `buy_url`, если он указан.
5. Если автоматической ссылки нет — сообщить предусмотренную инструкцию покупки или передать запрос администратору.

Никаких самостоятельно придуманных способов оплаты.

---

## 13. Передача администратору

`VK_ADMIN_ID` использовать для сценариев, требующих человека.

Примеры:

- пользователь просит связаться с Ириной;
- вопроса нет в базе знаний;
- проблема с оплатой;
- конфликтная ситуация;
- индивидуальный заказ;
- техническая проблема;
- бот не уверен в ответе.

При передаче желательно отправлять администратору:

```text
Нужна помощь в диалоге.

VK user_id: ...
Причина: ...
Последнее сообщение: ...
```

---

## 14. Защита от повторной обработки

VK Long Poll может повторно доставить событие или приложение может перезапуститься.

Желательно учитывать идентификаторы сообщений/событий и не отвечать дважды на одно сообщение.

Также бот должен игнорировать:

- собственные исходящие сообщения;
- неподдерживаемые события;
- служебные события, которые не являются пользовательским текстовым сообщением.

---

## 15. Ошибки API

При временной ошибке Kie.ai бот не должен показывать пользователю traceback или технические детали.

Допустимый ответ:

> Кажется, у меня сейчас небольшая техническая заминка. Попробуйте написать ещё раз чуть позже 😊

Ошибки логировать на сервере.

Никогда не записывать API-ключи в логи.

- вставлять токены непосредственно в Python;

## 18. Этапы разработки

### Этап 1 — VK

Сделать минимального бота:

```text
Пользователь → VK → Python → фиксированный ответ → VK
```

Проверить работу на BotHost.

### Этап 2 — Kie.ai

Добавить:

```text
VK → Python → Kie.ai → Python → VK
```

### Этап 3 — память

Добавить SQLite и отдельную историю по `user_id`.

### Этап 4 — knowledge

Подключить `knowledge.md` как основу системного промта.

### Этап 5 — каталог

Создать `products.json` и запретить модели продавать товары, которых в нём нет.

### Этап 6 — продажи

Добавить сценарии:

- подбор;
- уточнение;
- рекомендации;
- ответы на возражения;
- переход к покупке;
- handoff администратору.

### Этап 7 — тестирование

Проверить минимум такие сценарии:

1. «Здравствуйте».
2. «Что у вас есть?»
3. «Нужно для девочки 7 лет».
4. «Есть Present Simple?»
5. «Сколько стоит?»
6. «Дорого».
7. «Хочу купить».
8. «Дайте скидку».
9. «Позовите Ирину».
10. Запрос несуществующего материала.
11. Вопрос, ответа на который нет.
12. 10+ последовательных сообщений.
13. Одновременный диалог двух пользователей.
14. Перезапуск BotHost.
15. Ошибка AI API.

## 19. Критерии готовности MVP

MVP считается готовым, если:

- VK получает и отправляет сообщения;
- разные пользователи имеют раздельную память;
- память переживает перезапуск приложения;
- AI получает `knowledge.md`;
- бот знает актуальный каталог;
- бот не выдумывает товары и цены;
- бот умеет подобрать товар;
- бот умеет отвечать на обычные вопросы;
- бот мягко предлагает покупку;
- бот корректно обрабатывает намерение купить;
- неизвестные/сложные ситуации можно передать администратору;
- секреты отсутствуют в репозитории.

---

## 20. Важный принцип разработки

Сначала сделать надёжный MVP. Не добавлять админ-панель, аналитику, сложную CRM и другие дополнительные функции, пока базовая цепочка:

```text
VK → память → AI → каталог → ответ → продажа
```

не работает стабильно.
